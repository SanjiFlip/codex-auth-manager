# v0.5.0 界面与性能验证

日期：2026-09-21。此文记录 v0.5.0 界面与性能改动的合成数据测量；跨平台发布检查另见 [验证记录](VALIDATION.md)。

## 界面与操作

- 账号、用量、订阅额度、蒸馏、记忆、操作记录、体检和设置共 8 页使用同一套颜色、排版和控件；支持浅色 / 深色主题。
- 账号列表位于趋势图之前。Pro 默认不展示五小时额度，周额度占用完整宽度；开关仅影响显示，不改变订阅限制。
- 蒸馏分为会话素材、生成设置和草稿审阅。v0.5.0 基线为每页 50 个会话、24 条消息；支持跨页选择、只看已选、跨页全选 / 取消全选、选择上限和素材变化后重新审阅。
- 模型与推理强度直接从本机目录选择，项目分类与补充要求按需展开。进度事件仅更新状态和按钮，不重建表单；勾选消息保留 DOM、输入焦点和滚动位置。
- 记忆库每页 24 条，支持组合筛选、最近更新 / 标题排序、无结果时清除筛选；异步保存 / 删除防止重复提交。
- 主页面显示的数据没有变化时保留 DOM；主窗口手动刷新先更新本地记录。悬浮窗忽略与额度无关的知识任务通知。
- 360 × 560 悬浮窗中 Pro、Plus 两种布局均无需滚动即可看到底部入口，保留账号选择、确认切换、置顶与刷新操作。

## 性能机制

本地数据缓存合并相同请求的在途读取；缓存失效后，早先请求不能把旧值重新放回缓存。会话项目索引列表缓存 15 秒，手动「重新读取」强制刷新。读取正文前始终检查目录边界、实际路径及文件 size / mtime / ctime / inode；追加或替换文件会重新解析。

正文使用流式解析，仅保留最近 500 条消息。内存缓存最多 6 份结果、400 万正文字符，超出预算的单份结果不会缓存。这是内容缓存上限，不是整个应用的内存上限。

## 可复现对比

```sh
node scripts/performance-benchmark.js 55e95f0
npx electron scripts/design-smoke.js
```

基线为优化前提交 `55e95f0`。夹具包含启用项目索引和 201 个合成会话文件，其中一个有 4000 条正文；不扫描个人目录。下面是一轮 Windows 测量，首次指应用缓存未命中，操作系统文件缓存未清空，绝对耗时不能推算为所有机器的速度提升。

| 项目 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 同时请求同一数据 12 次的实际 loader 调用 | 12 次 | 1 次 |
| 首次列出 201 个会话 | 216.46 ms | 51.58 ms |
| 列表缓存有效期间连续读取 5 次 | 985.96 ms | 0.01 ms |
| 首次解析 4000 条正文 | 9.33 ms | 24.27 ms |
| 不变正文再次读取 5 次 | 44.28 ms | 8.06 ms |
| 500 条消息的首屏消息节点数 | 500 | 24 |
| 250 条知识记录的首屏卡片数 | 250 | 24 |

流式解析的首次耗时增加，换取按行读取和受限的消息留存；主要收益来自重复读取缓存、共享并发请求与减少 DOM。没有测量或宣称全应用启动速度、常驻内存或真实大库耗时下降比例。

## 检查范围

- 单元测试：Windows 56 通过，1 项 macOS 原生检查按平台跳过。
- 视觉与交互脚本：8 页在 1400 × 940 和 1000 × 820 窗口检查横向溢出，输出浅色 / 深色截图；检查 Pro / Plus 悬浮窗、账号搜索、消息分页与跨页选择、原位勾选、素材变更、记忆检索、任务进度焦点保留和无变化刷新。
- 蒸馏集成：真实 main / preload / 系统加密，合成账号、会话与模型响应；保存、导出、重载、取消和账号切换保护。
- 额度回归：文件监听、官方手动刷新、后续本地快照、同周期异常零值、定时读取及日志轮换。两个窗口更新，自动读取不调用远程服务。
- 本地模型列表、推理强度组合、归档过滤、项目移除、旧版项目名称、缓存命中后的归档复查与缺失索引拒绝均有专门测试。
- 实际 Windows EXE 启动、系统加密、悬浮窗、Pro 设置广播及无自动远程查询通过；打包后的知识流程检查通过，57 个源码与资源和 ASAR 逐字节一致。
- 测试使用隔离目录。当前变更未进行真实账号切换，也未在 macOS 上运行新版集成检查；已将界面脚本加入 macOS CI 待执行。

脚本输出位于忽略提交的 `output/design/`。README 的开发版图片使用合成内容；发布版截图保持原有版本归属。

2026-09-22 本地更新：会话导航改为项目折叠与按需展开，项目/会话勾选仅保留消息序号、指纹和长度；正文仍使用有界缓存。分批蒸馏与批量选择验证见 [验证记录](VALIDATION.md)。上表既有时间测量属于原测量版本，不能视为新流程的耗时测量。

## v0.6.2 大列表优化（2026-09-22）

新增 `npx electron scripts/knowledge-performance-smoke.js`，使用 3000 个合成会话、100 个项目，批量选中其中 30 个会话。先在优化前 UI 上复现重复遍历，再以相同夹具复测：

| 合成操作 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 项目属性读取次数 | 18,606,000 | 18,000 |
| 选择控件 DOM 查询次数 | 93 | 6 |
| 单轮 UI 操作耗时 | 1143.6 ms | 7.5 ms |
| 100 技能匹配 100 条配置时 realpath 调用 | 10,000 | 100 |

耗时仅为本机一次合成测量，不包含真实磁盘和 IPC 读取成本；操作次数是回归检查的主要依据。每次扫描单独解析 Skills 配置路径，不跨扫描缓存，链接目标变化后会重新读取。选择仍保留归档门禁、半选语义、取消与失败时不应用部分结果。
