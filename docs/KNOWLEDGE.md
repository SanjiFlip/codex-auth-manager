# 蒸馏工作台与记忆库

本文描述 v0.6.0 预览版的蒸馏工作台和记忆库，包括项目与会话勾选、结构化分批蒸馏及断点续跑。

## 使用前准备

- Windows / macOS 安装官方 Codex CLI，并使用 ChatGPT 账号登录。管理工具需启用文件凭据管理。
- 本机验证 CLI 为 0.154.0；需要支持 `exec --ignore-user-config --ignore-rules --ephemeral --json --output-schema`。旧版本不支持时应升级 CLI，不回退到交互终端。
- 模型下拉框直接读取本机 `models_cache.json` 中可展示的模型；推理强度只列出该模型声明支持的值。默认选中本机 `config.toml` 的模型与强度（有效时），否则使用目录默认值。读取列表不会联网、启动 CLI 或弹出终端。
- 缓存只是本机最后一次获取的目录，不能证明账号此刻的在线权限。没有缓存时，先在 Codex 中加载模型列表，再点击「重新读取」。开始蒸馏前后端会再次校验组合，并显式传入 `--model` 与 `model_reasoning_effort`；不会继承自定义模型代理、MCP 或 hooks。

## 蒸馏流程

1. 打开「蒸馏工作台」，点击「读取本机会话」。仅列出当前启用项目中的未归档 Codex 会话，默认显示全部时间，可按项目名称、会话 ID 或最近 7 / 30 天筛选。项目使用 Codex 中的名称，不显示目录路径。
2. 点击项目名称展开会话；会话标题左侧可勾选全部可选正文，项目名称左侧可勾选整个项目中已读取的会话（包含折叠、搜索与时间筛选外的会话）。半选表示只选了部分内容，再次点击补全选择，全选后点击取消。也可点击会话，在右侧勾选具体用户或助手消息。可以跨会话、跨页选取；每页展示 24 条消息，可「全选」当前会话全部可选消息（包含其他分页），再次点击「取消全选」。也可「只看已选」。不再提供独立的「清空」按钮。工具输出、系统消息和分析通道不作为素材。
3. 选择 Skill、工作流、提示词、个人偏好或任务记忆，填写标题，选择本机模型和推理强度；项目分类与补充要求位于可展开设置中。
4. 点击「预览并开始蒸馏」，核对模型、推理强度、各会话消息数量、发送范围和调用批次，确认后使用当前账号调用官方模型。预览期间修改工作台不会改变本次确认的配置和素材；如需使用新选择，请返回后重新预览。任务会消耗该账号额度。
5. 草稿生成后查看、编辑并保存到记忆库，也可直接导出 Markdown。生成结果需自行核实，来源引用帮助回看，但不是事实正确性的保证。

批量读取时可取消，失败或取消不会应用部分勾选。生成时点击「暂停并保存进度」停止当前调用；成功校验的批次已加密保存。每次模型调用最长 3 分钟，顺序执行，不自动重试。退出应用会暂停；意外退出后重新打开工作台也会发现未完成任务，不自动继续消耗额度。

## 大项目自动分批与断点续跑

原来的 24 万字符总量与 20 批提取限制已移除。当前单任务支持最多 3000 个会话、1200 万字符、2048 个提取批次，仍是本工具的资源保护值，不是账号或模型的官方上限。字符按 JavaScript 字符串长度计数，不等同于 token。开始前显示实际字符量、提取批次与保守估计的调用上界。

- 先把所选正文自动打包为不超过 24000 字符的引用素材 JSON。编码后超过单批的消息拆为连续片段，保留原会话 / 消息编号，不静默截断。
- 每批最多提取 12 条带原文摘录的证据。证据多时，每组最多 12 个节点整合为最多 4 个节点，逐层收敛后生成最终草稿。每层校验引用 ID、全输入关联和原始证据映射。
- 每个成功校验的模型返回独立、原子地加密保存。失败后点击「从断点继续」使用原模型与推理强度，并使用本机当前账号。已经保存的调用跳过；未落盘的调用可能重新执行，不能保证远端请求恰好执行一次。
- 重启后不必重新勾选，但原始会话仍须在本机可读、未归档且属于启用项目，所选正文指纹与分批内容须匹配。内容变化、滚动读取范围变化、模型不可用或检查点损坏时保留记录并报错，不混用旧结果。
- 当前保留一个未完成任务。开始另一个任务前，先继续完成或点击「放弃此任务」删除恢复记录。放弃不删除原会话和已保存的草稿。
- 最终正文最多 80000 字符，展示简短证据预览；全部提取证据及章节关联随草稿加密保存，导出 Markdown 时完整附带。来源关联覆盖不意味着语义没有遗漏，仍需审阅。

大项目勾选范围仍是各会话已加载的可选正文，不等于整份历史：单会话读取范围仍为末尾 8 MB 内最近 500 条消息，单条超过 20000 字符只供查看。任务运行期间本工具禁止切换账号；暂停后可以切换，续跑会明确使用当前账号，工具无法阻止外部程序改动凭据。

## 记忆与 Skill 如何复用

- 每页最多 24 个知识条目，可按最近更新或标题排序；支持搜索、类型与状态组合筛选，无结果时可一键清除筛选。
- 所有类型都可按项目归类、搜索、编辑、删除和导出；个人偏好与任务记忆是两种独立类型。
- 记忆属于本机知识库，跨账号共用，不随当前账号切换而改变。
- Markdown 可作为下一次会话的附件或上下文。保存到这里不意味着 Codex 自动读取。
- Skill 导出为包含 `name` / `description` 的 `SKILL.md`，正文包含方法与适用边界；第一版不生成脚本包、不自动安装，不写入现有 Skills Hub 或 Codex 记忆目录。
- 删除条目不删除原始会话或已经导出的文件。编辑冲突会要求刷新，避免覆盖其他窗口的修改。

## 数据与运行边界

- 只按用户操作读取 CODEX_HOME 的本机项目与会话索引（`state_*.sqlite` 和必要的桌面项目设置）。仅接受 Codex 来源、未归档且属于启用项目的会话，之后才打开 `sessions` 中对应的 `.jsonl`。不会读取项目目录内的代码或数据，也不读取归档目录、已移除项目、ChatGPT 项目或子代理会话。
- 读取正文、缓存命中和开始蒸馏前都会复查归档 / 项目状态。缺少索引或无法确认状态时明确报错，不退回全盘会话扫描。旧版项目名称从 Codex 的本地项目配置读取。
- 列表包含项目索引中全部符合条件的会话，不再因超过 300 个、正文超过 32 MB 或文件修改时间较旧而隐藏。按索引中的活动时间筛选；旧正文路径失效时，只按已获准的会话 ID 查找 sessions 内文件名，不扫描未知正文。缺失正文的会话仍显示“未就绪”。
- 项目默认折叠，展开先显示 5 个会话标题，「展开显示」每次增加 20 个；正文每页 24 条。目录缓存 15 秒，点击「重新读取」立即重扫；正文缓存会核对文件变化，并限制为 6 个会话、400 万字符。重新打开会话发现已选正文变化时，会取消旧选择并提示重新审阅。
- 每次蒸馏最多选择 3000 个会话、共 1200 万字符。正文按需读取文件末尾最多 8 MB 内最近 500 条用户/助手消息；大文件的更早正文不在本次全选范围内，界面会提示。窗口内的消息序号配合指纹校验，不是大文件的绝对行号。单条超过 20000 字符时仅供查看，不能勾选。超过总字符限制会明确报错，不截断后悄悄发送。
- 发送内容为选中的正文、标题、补充要求与应用提示词。尝试遮盖常见令牌字段，但不能保证识别所有敏感文本；发送前应检查选中内容。
- CLI 使用独立临时工作目录、只读沙箱和非交互模式，禁用 shell、MCP 用户配置、插件、记忆、hooks 等相关能力，不加载项目 AGENTS.md。CLI 的临时模式不保存本次会话正文。
- 使用现有 CODEX_HOME 中的当前文件登录，不复制或输出账号令牌；CLI 仍可能正常刷新自己的登录凭据。
- 知识库位于管理工具数据目录的 `knowledge/knowledge.enc`，通过 Electron safeStorage 使用 Windows DPAPI / macOS Keychain 保护整个内容，包括标题、正文和来源。解密失败时保留原文件并报错，不静默清空。
- 知识库保存草稿、完整提取证据、章节关联、用于引用核对的短摘录、来源消息序号与指纹；不复制完整会话文件。导出的 Markdown 为明文；请自行选择保存位置。当前账号凭据的加密迁移功能不包含知识库，知识跨设备复用通过 Markdown 导出。
- 未完成任务的选择信息保存在 `knowledge/jobs/current.enc`，经过校验的结果分文件保存在任务子目录，同样使用系统加密；不保存完整原始会话快照。完成并入库后清理检查点，草稿按任务 ID 去重。
- 知识库目前最多 1000 条，每条正文最多 80000 字符，完整证据独立于正文长度；列表不会把完整证据传到页面。

归档变化处理：读取列表与蒸馏前会重新核对可用会话。列表加载后才归档的聊天在点击时自动移除，其已选消息一起取消，不读取归档正文；Windows 扩展路径先解析为同一个真实文件再比较。

## 后续界面调整

会话素材左侧采用项目分组。默认折叠，点击项目名称后显示 5 个会话标题；「展开显示」逐步展示更多。点击会话后，右侧才读取并展示正文。列表不重复显示日期、项目路径或消息数量；长标题可悬停查看。搜索项目或会话时自动展开匹配组，折叠不清除已选消息。此布局自 v0.6.0 起提供。


## 分批蒸馏与校验

当前采用分批提取 → 有界多层整合 → 最终草稿的流程，详情见上文「大项目自动分批与断点续跑」。预览只在本机复查范围与指纹，不调用模型；开始与续跑再次核对。所有模型步骤使用 `--output-schema` 并独立校验，再写加密检查点。

提取结果的来源编号和连续原文摘录必须匹配，用户偏好必须有用户原文支持。每层整合只能引用本组有效 ID，程序要求全部输入 ID 有关联；保留完整叶子证据和章节映射。程序不能证明语义完整、推理正确或 uncertain 没有在自然语言中被误写成确定结论，需人工核对最终草稿和证据档案。
